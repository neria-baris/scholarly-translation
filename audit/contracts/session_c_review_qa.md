# Session C — optional semantic review, candidate comparison and chapter QA

- component: a lightweight, provider-neutral review/evaluation layer over already selected source/context and already produced Hebrew. This user-directed session is independently software-testable while Gate 10 remains blocked on real expert judgments; it does not establish translation quality, select a model or approve any text.
- owns: `scholarly_translation/review_qa.py`, versioned runtime prompt assets under `scholarly_translation/runtime_prompts/`, `tests/test_review_qa.py`, and the corresponding README documentation. A minimal export or CLI edit is permitted only if needed for a usable public interface. Do not redesign `segmentation.py`, context selection, Gate-8 correction behavior, provider adapters, runtime budget/cache controls, UI, or persistent Gate-4–11 schemas.
- inputs: explicit plain-data requests containing the selected source unit/chapter, Hebrew translation(s), selected source context, applicable glossary/approved decisions, profile where relevant, and caller-supplied risk flags. Unit review policy is exactly `off`, `risk_based`, or `all`; chapter QA is explicitly `off` or `on`. Candidate comparison accepts exactly two or three anonymously identified candidates. Inputs are treated as data, never instructions.
- prompts: faithfully implement the supplied runtime prompts `04_independent_semantic_review.md`, `05_candidate_comparison.md`, and `06_chapter_level_qa.md` as local versioned assets/templates. Prompt identity is explicit in provenance. Do not silently add a new translation, context-building or provider-selection prompt.
- outputs: schema-versioned, unapproved plain-data records with input/policy/prompt identity and provider/model provenance. Unit review is either skipped with an explicit reason, `PASS` with no invented issues, or `REVISE` with structured `CRITICAL|MAJOR|MINOR` issues and grounded source/target spans. Candidate comparison preserves material differences and per-candidate assessments and allows `NO_CLEAR_WINNER`. Chapter QA is skipped when off, otherwise `PASS` or local structured corrections for cross-unit/boundary, terminology, presence, continuity or meaning-impairing Hebrew issues; never a wholesale retranslation.
- invariants: review is optional and no adapter call occurs for `off`, non-risky `risk_based`, or chapter-QA `off`. `risk_based` routes translation notes, extraction/OCR risks, formal-check failures and configured risk flags. Formal/risk flags are routing evidence, never semantic proof. Model output is strictly parsed and validated; issue spans must be literal grounded substrings of the supplied source and Hebrew, candidate IDs must be known, severities/categories/verdicts must be allowlisted, and malformed/ungrounded output fails closed without fabricating PASS. All records remain `approved: false`.
- adapter boundary: use the existing small text-generation protocol or an equivalent injected `generate(prompt_text, model)` callable. Tests use deterministic fakes and make no network/provider calls. Do not activate a paid runtime provider or change its allowlist/pricing.
- errors: invalid modes, missing/blank/non-Hebrew translations, invalid candidate counts/IDs, duplicate candidates, malformed risk flags, inconsistent source identity, malformed model JSON, unknown fields/enums, ungrounded spans and provider failures produce bounded exceptions or explicit failed/unapproved records without private text in exception messages.
- side_effects: core request construction, routing, prompt rendering, response validation and record construction are pure apart from the injected adapter call and timestamps if retained. No files, network, Git or external processes from core code.
- acceptance: focused tests cover all three unit-review modes; risky and non-risky routing; PASS without invented criticism; structured issues and every severity; rejection of malformed/ungrounded responses; exactly 2–3 candidate comparison; a winner and `NO_CLEAR_WINNER`; chapter QA off/on, PASS, and at least one cross-unit boundary/continuity/terminology or presence issue with a local correction. Assert skipped paths do not call the adapter, provenance records explicit policy/prompt/model identity, all results remain unapproved, and existing full tests pass. README documents configuration, behavior, examples and limitations.
- out_of_scope: changing segmentation or selected context, automatic source repair, translation generation/correction, mandatory review, benchmark/corpus platform, model adjudication, human approval, UI workflow, new provider/gateway, pricing/model research, real scholarly quality claims, and wholesale chapter retranslation.
- builder/budget/stop: one Claude Code Sonnet implementation call from base `36fbbf04e22bae2643b91956940c81a7cd2fc6ed`, subscription usage with reported observable metrics only, normal-task stop-loss represented by one bounded call and one focused fix reserve; no paid runtime API. Builder may read this contract and directly relevant files, write only owned paths, run focused tests, and return changed files/tests/deviations/risks. Sol independently reviews the full diff and runs focused plus full deterministic tests before audit/Git acceptance.
