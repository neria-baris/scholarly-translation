- Component: provider-independent diagnostic request/result boundary with a mock adapter and one optional OpenAI Responses adapter. Sol is conductor; scoped Sonnet builder. Base ea6bb6898ccd159798734169a4d14d975cf40bfc. Gates 1–5 remain unchanged. This is provider plumbing, not the Gate-7 translation workflow or model-quality selection.
- Owns: new `scholarly_translation/model_adapter.py`, focused `tests/test_model_adapter.py`, minimal CLI addition in `scholarly_translation/__main__.py`, README Gate-6 section and optional dependency instructions. Do not edit existing source/segmentation/glossary/memory schemas, old tests, policy or audit. No Git, shell, web, delegation or paid calls from builder.
- Input: a small, explicit diagnostic request schema 1 containing `profile_id=scholarly`, synthetic marker, source language, target `he`, source text and SHA-256, prompt/config version, provider/model selection, and a caller-supplied request ID. Validate exact fields/types, source hash and bounded text before adapter call. Unsupported profile/provider/model fails; mock and OpenAI share the same request/result shape. Gate 7 will construct real source-bound translation jobs from validated Gate-4/5 artifacts.
- Output: schema-1 diagnostic result with status (`mock_placeholder`, `completed_unapproved`, or explicit failure), profile/request/model/prompt identity, response text only for success, timestamp/duration, observed token usage (input/output/cached/cache-write/reasoning when present), pricing version, list-price estimate or `not_metered`, actual charge `unknown` for API, and no human approval. The result is never translation memory, final translation or export.
- Mock: deterministic conspicuous placeholder; no network, no secret needed, non-billed event. Test adapter substitution with a fake client. Keep Gate-1 `provider.py` behavior intact.
- OpenAI: exact model `gpt-6-luna`, Responses API via official Python SDK, imported only for real calls. SDK reads `OPENAI_API_KEY` from process environment; never accept/store/log the value. No key or SDK gives an explicit local setup error before network. `store=False`, no tools, `reasoning.effort=none`, `max_output_tokens<=256`, at most one network attempt (`max_retries=0`) and finite timeout <=20s. Only synthetic test text is sent at this gate. No account or document data in the smoke test. Do not call API from tests or builder task.
- Budget/usage: one live probe only after a detectable key and installed SDK, user-facing provider/model/purpose/cost notice, and preflight confirming current official model/price/SDK. Standard list rates recorded as $0.10/M input, $0.01/M cached input, $0.125/M cache write, $0.50/M output (verified 2026-09-30); estimate from reported usage, separate from actual charge. Fixed diagnostic text plus 256 output cap is estimated below $0.01; Gate-6 runtime-call cap $0.01 and no automatic retries. If reported usage is missing, record `not_metered`, do not invent a charge. No runtime provider enabled by mere CLI login.
- Public interface: one `probe-provider --provider mock|openai --output OUTPUT_DIR` command using a fixed, small synthetic English phrase and the same contract/adapter. Output under ignored local `outputs/`; refuse input/evidence overwrite, invalid configuration and unsafe path. Dry mock probe works without credentials or SDK; OpenAI probe refuses to run until configured. Output JSON/usage excludes credentials and need not retain raw API response. Print only summary metadata, not a key or private source.
- Invariants/errors: no silent fallback from OpenAI to mock; no source mutation, real approval, retries or tools. Error messages omit request text/key and are bounded. Transport failures produce nonzero CLI and a sanitized status/usage event where observable; do not log secrets. Pricing calculation handles missing/invalid usage safely. Model response must be completed with nonempty text; incomplete/empty is an explicit failure, never approved.
- Acceptance: full existing suite; pure request/result and usage negatives; mock CLI round trip; fake SDK client verifies exact request parameters, no network/retry on missing key, timeout and usage/cost parsing; adapter substitution; invalid profile/model/text/hash and malformed response rejected; no private text in errors/logs. One real small OpenAI call, its usage/timeout and remote status recorded, is required for Gate-6 PASS. With no key, record software construction as verified but Gate 6 BLOCKED for live-call acceptance; continue only independent work.
