# UI source and terminology decisions

- Component: local browser forms for Gate-4 source selection and Gate-5 terminology proposals/reviews. User requested this extension on 2026-10-01. Sol owns integration, checks and Git.
- Inputs: validated local structure and optional glossary under ignored outputs; a selected exact page/candidate or resolved unit/current rule; explicit human actor and reason for consequential decisions. Existing CLI contracts and persisted schemas remain authoritative.
- Outputs: new ignored action JSON and a new versioned `structure.json` or `glossary.json` produced by the existing public CLI. Earlier artifacts remain intact. The UI returns new artifact paths and status, never approval from a display click alone.
- Invariants: source decisions bind page ID, origin, exact candidate hash and expected structure revision; preserve earlier decisions on other pages; reject unusable/stale candidates. Terminology proposals bind an exact source term occurrence/span in a resolved unit and default to unit scope. Approval/rejection binds current rule ID/version/fingerprint plus nonempty human actor/reason; pending rules stay pending until that action succeeds. The backend validates inputs and uses the CLI to create the new artifact. No model or paid provider call.
- Errors/side effects: invalid/stale fields fail before writing; output generation is restricted to unique ignored `outputs/ui` directories. CLI failure returns a bounded error and never advances the UI's selected artifacts. Generated action files are local evidence, not Git material.
- Acceptance: real synthetic PDF extraction produces unresolved source options; explicit browser choice resolves it while preserving lineage; wrong hash/stale revision/model actor is rejected. A source-bound term can be proposed, approved/rejected with exact current version, and a stale review is refused; prior glossary file remains unchanged. Existing suite passes. Synthetic actions do not establish scholarly quality.
- Out of scope: automatic source reconstruction, term approval by a model, altering Gate-4/5 schemas, public service exposure, or quality/release acceptance.
