# Gate 2 — digital PDF extraction

- component: local digital PDF extraction; owner Sol, scoped builder Sonnet.
- owns: scholarly_translation/pdf_extract.py, records.py, __main__.py; tests/test_pdf_extract.py; tests/pdf_fixture.py; requirements.txt; README.md. No other writes, audit/Git, web, shell, agents or future gates.
- input: actual PDF bytes/path, language, positive document version; pdfplumber 0.11.8. Source identity is PDF SHA-256, independent of path. Fixture generator uses reportlab 5.0.1, original tiny two-page English/French content with heading, footnote marker/note, number, citation, ASCII formula, deliberately shuffled draw order. Never commit PDFs.
- output: Document schema 3; schema 1/2 explicitly remain readable. Extend Segment with optional bbox [x0,top,x1,bottom] in PDF points, Page with optional width/height/source_text. PDF pages require dimensions and exact extracted source_text, segments point to exact page-local spans and bbox. Never normalize, translate or delete source. IDs stable on repeat/path relocation, distinguish changed bytes/version. Stage digital-pdf@1, measured PDF hash, status needs_human, warnings layout_unverified (extraction is not semantic acceptance).
- invariants: each extracted line preserved including header/footnote/formula/numbers; exact span slices; page/bbox bounds, finite values/types; no source overwrite. Basic top-to-bottom then left-to-right reading order only; warn unsupported layouts/empty text, do not claim multicolumn or Japanese vertical order correctness. Empty pages retained and flagged needs_ocr. No footnote semantic inference in this gate.
- errors: invalid/empty/encrypted/missing PDF -> bounded ExtractionError without private content; malformed persisted geometry -> RecordValidationError; empty pages not silently omitted.
- side_effects: explicit output JSON and optional rendered page PNG plus escaped static HTML comparison. Render through pdfplumber page.to_image at 110 DPI (PDFium available); original source URI+page number retained. No network.
- acceptance: public `extract-pdf INPUT --language en --output outputs/gate2` writes document.json, page-N.png and comparison.html; actual CLI inspect consumes it. Tests generate actual two-page PDF in temporary dirs, assert expected exact strings/reading order/footnote/formula/all pages/spans/bboxes/stable IDs/hash/legacy reads; missing/corrupt/blank PDF/invalid bbox negative cases. Conductor independently runs tests and inspects rendered page image beside extraction. Tests must pass with .venv/Scripts/python -B -m unittest discover -s tests -q. Existing Gate 1 tests stay meaningful.
- out_of_scope: OCR, paragraph/footnote linking, semantic reconstruction, translations, runtime APIs, UI/server, quality on real scholarly PDFs. Fixture is software evidence only.
- budget: one Sonnet implementation call, estimate ceiling $2 via CLI; one targeted fix reserve $1 only for demonstrated failure; actual subscription charges unknown. Tool soft limit 20/hard instruction limit 60, wall timeout 10 minutes; no approval model. Conductor tests, builder no Bash.
- stop: return concise changed paths and limitations, no PASS/commit. Do not reread entire repository; read this contract and affected files only.
