# Gate 7 — first source-bound translation draft and formal checks

- Component: the smallest scholarly-profile translation job from an existing validated Gate-4 unit and Gate-5 glossary resolution through a replaceable mock/OpenAI text adapter to an unapproved Hebrew draft plus deterministic findings. Sol conducts; one scoped Sonnet builder. Base 2fa1208a2cd2346749b14f25fbea3b288f48c03a. Gate 6 diagnostic remains separate. This gate does not select a quality winner.
- Owns: new `scholarly_translation/translation.py` and `scholarly_translation/formal_checks.py`; focused `tests/test_translation.py`; minimal generic text-generation adapter addition to `model_adapter.py`; `translate-unit` CLI addition to `__main__.py` and README. No edits to Gate-1–5 source, OCR, structure, glossary or memory schemas/tests; no audit/Git/dependency changes by builder. Builder uses Read/Write/Edit only, no shell/web/agents or paid runtime calls.
- Input: `validate_structure` on persisted schema-1 structure; `validate_glossary` and fresh `resolve_applicable` for a caller-supplied `unit_id`; exact resolved reading and unit. `profile_id` is exactly `scholarly`; other values fail without fallback. Source language `en|fr|ja`, target `he`. Refuse unresolved reading, continuity findings, missing/stale unit, conflicting glossary resolution, malformed source/policy and oversized prompt before network. Proposed glossary rules are visible as risk metadata only, never instructions. No supplied free-form text bypasses source validation.
- Context/policy: include target unit and at most one previous/next unit from the same reading, with explicit roles and bounded characters; never cross page/document/readings or send a whole PDF. Pass only applicable approved rule source/target/version/loaded fields. Prompt/config version is `scholarly-first-draft@1`; no profile registry. Build a deterministic cache identity from profile, exact PDF/source/reading/unit spans and hashes, neighbor hashes, effective applicable-policy fingerprint, provider/model, prompt/config and decoding parameters. Record the key; no cross-profile or stale-policy reuse. No persistent cache or automatic translation-memory approval in this gate.
- Provider boundary: provider-independent resolved text request/result; mock produces conspicuous non-Hebrew placeholder and is never counted as a real translation. OpenAI path uses exact `gpt-6-luna` via official SDK, `store=False`, no tools, reasoning none, output cap 256, timeout <=20s and `max_retries=0`. Adapter receives a fully resolved prompt and contains no scholarly branching. Missing key/SDK fails before network; transport/incomplete/empty response is explicit failure and sanitized. Do not print/store the key or provider exception text. No silent fallback. Preserve Gate-6 diagnostic API and tests.
- Budget gateway: bound request UTF-8 bytes and output tokens so a conservative preflight estimate at standard list rates is below the per-job ceiling. For Gate-7 acceptance, at most one call each for en/fr/ja (three total), no retries, cumulative standard list-price cap $0.01, 50%/80% notices and stop before exceeding the cap. Actual charge remains `unknown`; do not claim an enforceable account-billing cap. If usage is absent/invalid, record `not_metered` and stop further live calls for the run. Record input/output/cached/cache-write/reasoning tokens when reported, pricing version, duration and failure status. Only synthetic fixture text is sent during gate acceptance.
- Output: schema-1 `translation-draft@1` with `profile_id`, source URI/PDF hash/document/page/reading/unit identity and versions/span/text hash, source language, target language, neighbor/context fingerprint, applicable glossary fingerprint and rule IDs/versions, provider/model and observed model identity if available, prompt/config version/hash, cache key, response status, Hebrew draft text or null, token usage/list estimate/actual charge and timestamp/duration, deterministic findings, `approved=false`. The draft is not approved memory, final translation, review or export. Source and glossary inputs remain byte-identical.
- Checks: separate pure checker over source and target that reports typed findings with exact source token/span and target evidence where possible for numbers, explicit proper-name candidates, footnote markers, citation/reference tokens and formula-like expressions. Unicode-normalized comparison is allowed for presentation equivalents; no silent rewrite, transliteration assertion or semantic truth claim. Missing/changed protected elements, missing Hebrew script or proposed loaded terminology produce `needs_human`/finding; a formally clean draft remains `draft_unapproved`. Formal failure must never set approval. Avoid claiming a name is wrong solely from a transliteration; mark uncertain candidates for human review.
- Public CLI: `translate-unit STRUCTURE_JSON --glossary GLOSSARY_JSON --unit-id UNIT_ID --profile scholarly --provider mock|openai --output OUTPUT_DIR`. Strict duplicate-key/nonfinite JSON reader; missing/malformed inputs return nonzero without traceback. Refuse output collision with structure/glossary/source evidence, existing draft or source/test tree. Write one `translation_draft.json` under ignored local `outputs/`, including failures with observable usage when a call occurred; print metadata only. Missing credential produces no call/output. Mock path works offline. CLI must not mutate input records or perform a hidden approval.
- Acceptance: full existing suite plus producer-consumer tests from constructed en/fr/ja source-bound structures (simulated explicit human source choices), applicable approved glossary and bounded same-reading neighbors. Fake clients verify exact provider parameters and dependency/cache-key changes on source boundary, neighbor, applicable glossary, profile/prompt/model; unrelated UI/glossary change does not invalidate. Negative cases for unresolved OCR, conflicting terminology, stale/malformed structure, oversized context, unsupported profile/language, missing SDK/key, transport/incomplete response, protected-number/name/note/citation/formula omissions and evidence overwrite. Public mock CLI round trip. One real small synthetic `gpt-6-luna` draft for each available source language en/fr/ja, with Hebrew script and recorded usage/cost/status; findings may still require human review. No quality PASS or human approval from those outputs.
