# Gate 10 contract — evidence-based quality pilot

- Component/owner: `evaluation.py` validates a human-labeled pilot manifest and computes a reproducible report. Sol owns contract, integration, audit, Git and pilot decision; one scoped Claude Code Sonnet builder may implement the offline harness. No model chooser or routing change until genuine gold evidence exists.
- Input: schema-1 pilot manifest referencing exact source PDF/reading/unit and approved Hebrew reference hashes; one or more comparable candidate runs per unit with translation provider/model/prompt/context/critic arm, shared glossary hash, draft hash and human review attestation, source language, genre, OCR level, explicit source word count/pages, observed/list-price-estimated cost/latency, correction minutes, and expert MQM-style span/error annotations (omission, addition, negation, scope, quantifier, modality, referent, terminology, ambiguity, note/citation/formula, Hebrew) with severity and actor. Keep research text, PDF bytes and references in ignored local files; committed tests use synthetic fixtures only.
- Output: schema-1 pilot report with input hash, distinct sample counts by language/genre/OCR and experimental arm; critical errors per 1,000 source words, severity counts, correction minutes/page, list-estimated cost/page, p50/p95 latency, reviewer false-positive/true-positive counts where annotations allow, paired context/reviewer measured deltas, missing-data flags and explicit uncertainty. A report from fewer than 72 distinct fully reviewed source segments (24 per en/fr/ja), missing paired arms or missing expert review is `preliminary`, with no model winner or routing recommendation. Actual account charges remain unknown unless directly observed.
- Invariants: do not infer semantic truth from model output, smooth metrics, or synthetic labels. Source/reference approval must be explicit human evidence. Group only comparable runs over the same exact source boundary and glossary/context policy. Preserve raw annotations, timestamps and arm definitions; no post-result threshold changes without a new version and audit. No source mutation or auto approval. Count expert critical errors by unique source span/type; report uncertainty and per-language results before any aggregate recommendation.
- Errors/side effects: malformed/duplicate/nonfinite JSON, stale source hashes, missing required values, inconsistent arm IDs/units or invalid annotation spans fail closed. Public `evaluate-pilot MANIFEST --output DIR` writes one exclusive JSON report under ignored local output and prints counts/status only; no provider call or new credential. Never commit user PDFs, Hebrew references, annotation data or generated sensitive reports.
- Offline acceptance: full existing suite plus synthetic manifest tests for en/fr/ja grouping, critical error counts/rates, minutes/cost per page, p50/p95 latency, paired-arm missingness, false positives, source/approval validation, unsupported language/category, duplicate/invalid values, and public CLI. Synthetic outcomes demonstrate arithmetic/software construction only. Full Gate-10 acceptance additionally requires genuine balanced gold set and expert judgments, a real bounded model comparison under a separately approved/verified cost contract, and a per-language/genre table plus uncertainty-aware recommendation.
- Out of scope: automatically generating expert labels, claiming reliability from 72 samples, dynamic routing before evidence, buying hardware/services, sending sensitive PDFs to models without a bounded contract, extra full reviewers before measured value.
- Development budget: one scoped Sonnet builder call, reported list-estimate ceiling $2.50, wall <=900s, one evidence-based focused fix reserve $1. Runtime paid provider calls 0 for offline harness. Actual subscription charge and Sol usage may be unknown; Opus/Astra 0.
