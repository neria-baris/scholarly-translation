# UI-LIBRARY-REDESIGN — the library design in the real application

2026-10-15. User (to Claude Code as conductor) asked to make the design prototyped on `design/pixel-library-prototypes` (`design/pixel-library/library.html`, commit 3581774) the official version: built into the real app, with an English version and the new logo. User approved the six-stage plan and asked to run all stages without stopping, merging into main at the end. Branch `feat/ui-library-redesign`, worktree `.claude/worktrees/ui-redesign`, base main a003633.

- Approach: re-skin and extend the existing interface. Keep `ui.html` IDs, `ui.js` logic and every server endpoint; add a theme layer (`ui-theme.css`) after `ui.css`, a cat module (`cat.js`/`cat.css`) and new components where behaviour changes (library shelf, bindery). Existing UI tests stay green; a test is revised only where its pinned behaviour is deliberately replaced, and the revision keeps the real semantics it guarded (payloads, ARIA, routes, fonts, partial downloads, confirmation before delete).
- Stages: 1 foundation (tokens, local Frank Ruhl Libre font route, header/logo/tab icon, buttons/cards/forms/dialogs, cat with perches on real elements, he/en); 2 library (shelf with 3D books and cover on hover/focus, detail card with real actions, tabs/search/sort/list view/more shelves); 3 translation start (drop zone, grouped options, summary card, readiness list, estimate/consent styling); 4 processing and result (bindery page turn and morphing letters mapped to real job phases/pause; decisions, result, review, notebook); 5 learning window; 6 full regression, English/accessibility pass, merge and checkpoint.
- Owns: `scholarly_translation/ui/{ui.html,ui.js,ui-theme.css,cat.js,cat.css,learning.html,learning.css}`, static routes in `web_ui.py` for those files and the bundled font, `tests/ui/test_ui_redesign.py`, revised UI tests where noted, `scripts/design/serve_ui_sandbox.py` (local verification server), evidence under ignored `outputs/ux/ui-redesign/`, this contract and audit.
- Inputs: existing endpoints and JSON shapes (`/document-library`, `/document-in-progress`, `/document-job`, `/document-download`, `/document-delete`, account, update, learning routes); bundled OFL font `assets/fonts/frankruhllibre/FrankRuhlLibre[wght].ttf`.
- Outputs: same behaviour and data flow, new presentation; the cat is decorative (aria-hidden thoughts, keyboard-pettable), local only.
- Invariants: no new network origin, no remote assets, no paid provider calls during verification (Auto mode only, isolated `SCHOLARLY_DATA_ROOT`, memory key store); permanent delete keeps its confirmation; drafts never shown as approved; the cat never covers controls or reading text and never changes input; preferences only in existing localStorage conventions.
- Errors: missing font or cat script must not break the app (fallback fonts, guarded `window.libraryCat?.`).
- Acceptance per stage: UI unit tests (baseline 182 pass, 3 pre-existing errors: two `No module named 'export'` imports, one Python 3.9 `write_text(newline=)`) with no new failures; new static tests; headless Chrome against the sandbox server in Hebrew and English at 1440 and 390, no console errors; screenshots reviewed.
- Out of scope: server behaviour changes, new endpoints beyond static files, model/budget logic, the public site.
- Side effects: local commits on the branch; merge to main at the end only after the full regression; no push without the usual remote checks.
