# Gate 9 contract — human review, approval and bilingual export

- Component/owner: local `human_review.py` binds the exact Gate-4/5 source, Gate-7 draft and Gate-8 review, renders a reviewable local HTML page, validates an explicit human decision, and exports approved source/target text. Sol owns contract, integration, audit and Git; one scoped Claude Code Sonnet builder owns implementation. No new provider call.
- Inputs: validated structure, glossary, schema-1 `translation-draft@1`, optional schema-1 `semantic-review@1` bound to that exact draft and current source/policy. A decision is a separate JSON submitted through a public CLI, with selected candidate text or a human edited Hebrew text, actor, reason, expected hashes, and explicit `approve` or `defer`. The screen may help download the decision; it must not silently create an approval. Source PDF/image bytes and all upstream records remain immutable.
- Outputs: (1) static local review HTML with source text and exact page/unit/span/evidence link or OCR image, Hebrew draft and correction candidate, flags, applicable glossary, and correction history; (2) schema-1 `human-review@1` record with source/policy/draft/review/candidate hashes, human actor and reason, action/status, formal recheck, timestamp and prior decision link if superseding; (3) basic escaped bilingual HTML with explicit LTR source and RTL Hebrew, preserved text/number/formula/reference characters and a link back to exact review unit and PDF page/span. Export only a currently valid `approved` human-review record; `needs_human_or_budget`, failed, stale or merely unapproved work is never shown as approved.
- Invariants: approval is per unit and per exact source/reading/unit version, applicable terminology policy, draft and optional semantic-review hash. An explicit human action, nonempty actor/reason and candidate is necessary. Recheck formal protected elements on the selected/edited text; unresolved formal failure cannot be approved without an explicit documented human correction. No model/mock action, default button, or supplied `actor_kind` can grant approval automatically. A revision creates a new derived record and preserves previous history; no overwrite of input or approval evidence. Unknown profile and stale source/policy/review fail closed.
- Errors/side effects: strict duplicate-key/nonfinite JSON parsing; safe HTML escaping; no script injection from source/draft/glossary; invalid paths or evidence collisions fail before write; write outputs exclusively under caller output directory. A local browser may open the static review page; no server, network, account or external script. No credential, secret, research input or generated output in Git.
- Acceptance: full suite plus synthetic en/fr/ja producer-consumer fixtures. Public CLI can render a review page, make an explicit test-only simulated human correction/approval, export and open bilingual HTML, and navigate its link to a specific source unit/page/span. Negative tests for stale/tampered draft/review/decision, nonhuman/implicit action, formal failure, missing review for risky work, `needs_human_or_budget` with no human approval, output overwrite, and HTML injection. An unresolved case stays reviewable but unapproved. Synthetic actor decisions prove software behavior only; actual translation quality and real human approval remain pending.
- Out of scope: production auth, hosted server, PDF annotation editor, WYSIWYG layout, mass approval, automatic model approval, real scholarly pilot, Gate-10 gold-set/model selection.
- Development budget: one Sonnet CLI builder call, reported list-estimate ceiling $3, wall <=900s, soft 35/hard 70 observed tool calls; one reproduced-defect focused fix reserve $1. Runtime paid model calls 0. Actual Claude subscription charge and Sol usage may be unknown; Opus/Astra 0.
