עזרה ושקיפות

העמוד הזה מסביר את כל השלבים, ההגדרות ועלויות האומדן של כלי התרגום המקומי. דף זה נבנה מהשרת המקומי שלכם ואינו שולח מידע לאף שרת חיצוני.

שלבי השימוש

  1. בחירת קובץ — PDF עם טקסט מוטמע (לא סריקה ללא טקסט) או EPUB, עד 25MB.
  2. אפשרויות — פרופיל תרגום (אקדמי/ספרותי), רמת בדיקה (מהיר/נבדק/מעמיק), מודל (Auto לתצוגת ניסיון מדומה, או מודל משלכם עם מפתח API), שפת מקור, תקציב (שדה חובה במודל משלכם; אין תקרה מובנית — המגבלה שתגדירו נאכפת כעצירה קשיחה, וההזמנה השמרנית חייבת להיכנס בתוכה), וגופן PDF.
  3. תרגום — לחיצה על הכפתור. במודל משלכם תתבקשו לאשר שליחה בפועל לספק/ים שנבחרו ולצפות באומדן עלות מראש.
  4. מעקב התקדמות — אחוז התקדמות אמיתי (לא מבוסס זמן), לפי פרקים/שלבים שהושלמו בפועל; אפשר להשהות ולהמשיך עבודה אוטומטית. אם התרגום נעצר, מופיעה תיבת החלטה עם הסבר ואפשרויות.
  5. תוצאה — הורדת הקובץ המתורגם (PDF/EPUB/HTML), בדיקה ועריכה ידנית אופציונלית, ושינוי גופן PDF ללא קריאה חוזרת למודל.
  6. הספרייה — כל התרגומים, המוכנים ואלה שבתהליך, נשמרים במחשב שלכם ונגישים מכפתור "הספרייה" בראש העמוד. פרטים.

מודלים, QA ומפתחות API

ה-Auto מדומה: אינו שולח טקסט לאף ספק, אינו מצריך מפתח, ומחזיר טקסט מקום-שמור בלבד — לעולם לא תרגום אמיתי.

במודל משלכם בוחרים מודל מתרגם מהקטלוג (למטה) או מגדירים מודל "אחר" (מזהה, ספק, ולכתובת תואמת-OpenAI גם endpoint). בדיקת האיכות (QA — "semantic_reviewer" ו-"chapter_qa") מוגדרת כברירת מחדל זהה למודל המתרגם, וניתן לשנות אותה בנפרד. המפתחות נשמרים בזיכרון השרת המקומי להרצה הנוכחית: לא בקובץ ההגדרות, לא ב-log, לא ב-localStorage של הדפדפן ולא במשתני סביבה. אם מסמנים "לזכור במחשב הזה", המפתח נשמר גם מוצפן במנהל האישורים של Windows בחשבון המשתמש שלכם ונטען מחדש כשהתוכנית נפתחת; הכפתור "מחיקת המפתחות השמורים מהמחשב" מוחק אותו משם. סמל המפתח בכותרת זהוב כשיש מפתח, ועם נקודה ירוקה כשהוא שמור במחשב. הפעלה חדשה של השרת מאפסת אותם; חידוש עבודה שהושהתה מבקש את המפתחות מחדש ומשתמש בעבודה שנשמרה.

בקטלוג הזה כתיבת מטמון עולה יותר מקלט רגיל, וקריאת מטמון זולה ממנו. כתיבת Claude קצרה נשמרת לחמש דקות; כתיבה לשעה יקרה יותר ומופיעה בנפרד. בחירת מטמון אינה מבטיחה פגיעה: הספק צריך לזהות קידומת זהה ולתמוך באפשרות. תוצאה מקומית שמורה יכולה לחסוך קריאה שלמה למודל.

במודלי OpenAI המופיעים כאן, מעל 272,000 טוקני קלט בבקשה יחידה תעריפי הקלט והמטמון מוכפלים פי 2 ותעריף הפלט פי 1.5 — על כל הבקשה. אומדן הפרויקט כולל זאת. מחירים רגילים אלה אינם מחירי מנוי Claude Code או ChatGPT, וחשבון API נפרד עשוי לכלול תנאים נוספים.

למודל "אחר" ללא תעריף שהוזן משתמשים בהנחת $4 למיליון טוקני קלט ו־$20 לפלט, ללא הנחת מטמון. זהו אומדן מסומן, שאינו מחיר רשמי ואינו תקרת חיוב מובטחת של ספק לא מוכר. אפשר להזין את התעריפים האמיתיים כדי לעדכן את החישוב.

מקורות המחיר והמגבלות, שנבדקו ב־5 באוקטובר 2026: GPT-6 Luna, GPT-6.1 Sol, Claude Sonnet 5.5, Claude Opus 5.5.

אי-ודאות טוקנים, קלט/פלט ועלות QA/cache

ספירת הטוקנים בתצוגה המקדימה היא אומדן עליון (upper bound), לא ספירה רשמית של הספק: טקסט מעורב (עברית/לטינית/יפנית) עלול להיספר שונה ממה שהספק יחשב בפועל בזמן השליחה האמיתית. האומדן ה"צפוי" מניח כ-35% ניצול תקרת הפלט, אפס תיקונים ואפס פגיעה ב-cache (cache miss מלא); האומדן השמרני ("תקרה") כולל גם תיקון חסום אחד ובדיקה חוזרת ממוקדת אחת, ומניח כתיבת cache מלאה. שני האומדנים אינם הצעת מחיר של הספק, ועלות בפועל (observed) עשויה להיות שונה — היא מוצגת בנפרד מהתקציב השמור/המתוכנן בזמן ריצה אמיתית.

פרופיל תרגום ורמת בדיקה

לפי תיאורי הספקים המקושרים למעלה, המודלים מיועדים לסוגי עבודה שונים. אלה תיאורי הספקים, ואינם דירוג של איכות התרגום לעברית בפרויקט.

Luna — משימות ממוקדות

מיועד לפי OpenAI למשימות ממוקדות בהיקף גדול, במחיר נמוך. הוא מאפשר לבדוק יותר דוגמאות בתקציב קטן; יש לבחון במיוחד מינוח וטיעונים מורכבים.

Sol — עבודה מקצועית מורכבת

כך OpenAI מתארת את המודל. מחיר הקלט והפלט הרגיל גבוה פי 20 מ־Luna; תוספת המחיר אינה ראיה לשיפור בתרגום המסוים שלכם.

Sonnet — מהירות ויכולת

Anthropic מתארת אותו כאיזון בין מהירות ליכולת. מחיר הקלט והפלט הרגיל זהה ל־Sol, אך תעריפי המטמון והחשיבה עשויים לשנות את העלות הכוללת.

Opus — עבודה ממושכת

מיועד לפי Anthropic לעבודה מורכבת וממושכת. מחיר הקלט והפלט כפול מ־Sonnet, וחשיבה תמיד פעילה; לא הוכח בפרויקט שהוא תמיד מתרגם או מבקר טוב יותר.

אפשר לבחור מתרגם זול ובודק אחר, או לבדוק דגימת מקור עם כמה מודלים. הבחירה הרצויה תלויה בדיוק במשמעות, במינוח, בסגנון ובממצאי QA של הטקסט שלכם; מחיר גבוה או חלון הקשר גדול לבדם אינם הוכחת איכות.

אקדמי שומר על דיוק סמנטי, מינוח, הערות שוליים וציטוטים. ספרותי שומר על קול, רגיסטר ודיאלוג.

מהיר: תרגום בלבד, ללא בדיקת QA שגרתית. נבדק: בדיקת כל מקטע שיש בו מה לתרגם, חוץ מכותרות קצרות (עד שלוש מילים), + בדיקת פרקים. מעמיק: בדיקת כל מקטע, כולל כותרות, + בדיקת פרקים.

ממצא מהותי (MAJOR או CRITICAL) מבדיקת מקטע מתוקן אוטומטית ונבדק שוב. מבדיקת הפרק מתוקנים אוטומטית רק ממצאי עקביות ורצף; שאר ממצאי בדיקת הפרק נשמרים כהערות. ממצא שהציטוט שלו לא נמצא בטקסט, או שהמודל חזר בו, מושמט ואינו מתוקן.

אין דירוג איכות מאומת למודלים. לא בוצע עדיין פיילוט איכות מחקרי עם שופטים אנושיים על מקטעי מקור אמיתיים (הפיילוט חסום כרגע בהיעדר קלט מייצג מאושר, הרשאת ספק ושיפוט אנושי). מודל יקר יותר אינו מובטח כאיכותי יותר לטקסט שלכם; מומלץ להריץ פיילוט קטן על חלק מהמסמך שלכם ולבדוק את ה-QA בעצמכם לפני שמסתמכים על מודל יחיד.

השהיה, חידוש ותוצאות

השהיה שומרת את תשובת הקריאה הפעילה ועוצרת לפני בקשה נוספת. המשך משתמש במקור, בתוכנית ובתוצאות השמורות: שלבים שכבר הושלמו אינם נשלחים ואינם מחויבים שוב. בקשה שתוצאתה לא ידועה אינה נשלחת שוב אוטומטית; היא מוצגת בתיבת החלטה כדי שתבחרו בעצמכם אם לשלוח שוב.

הורדה בונה את המסמך מהטיוטה השמורה. בדיקה ועריכה מציגה מקור לצד יעד ושומרת גרסה קודמת. אחרי עריכה, בדיקת האיכות הישנה מסומנת כלא מעודכנת; העריכה אינה אישור מחקרי.

האחוזים תחת הספר משקפים השלמת שלבים ופרקים, ואינם תחזית זמן. בהשהיה ובכשל הספר מפסיק להתדפדף. כל התוצאות הן טיוטות לא מאושרות, גם לאחר בדיקות אוטומטיות.

הספרייה

כפתור הספרייה בראש העמוד פותח את כל התרגומים השמורים במחשב, בשתי לשוניות:

  • מוכנים — תרגומים שהושלמו. לחיצה על מסמך מציגה הורדה בפורמט המקור (PDF או EPUB) או כ־HTML, בחירת גופן ל־PDF, ופתיחה לבדיקה ועריכה.
  • בתהליך עבודה — תרגומים שעדיין לא הושלמו: מושהים, שנעצרו או שהופסקו. לכל מסמך מוצגים מצב, פרקים ומקטעים שהושלמו, והוצאה מתוך התקציב. מסמך שמחכה להחלטה שלכם מסומן "נדרשת החלטה". פתיחה והמשך (או פתיחה והחלטה) מחזירה לחלון ההתקדמות.

הורדה חלקית (בלשונית "בתהליך עבודה") בונה קובץ ממה שכבר תורגם; מקטעים שעדיין לא תורגמו נשארים בשפת המקור. הסיומת .he.partial בשם הקובץ מבדילה אותו מתרגום מלא. ההורדה אינה שולחת קריאה למודל.

מחיקה מוחקת לצמיתות את התרגום, את ההעתק של קובץ המקור, את מחברת הספר ואת יומן העלויות של המסמך. תתבקשו לאשר, ואי אפשר לבטל. מסמך שמתורגם ברגע זה אי אפשר למחוק: השהו אותו קודם. מחיקה אינה מבטלת חיוב שכבר נרשם אצל הספק.

כשהתרגום נעצר

כדי לא לבזבז כסף ולא לחייב פעמיים, התרגום נעצר כשמשהו אינו ודאי, ומחכה להחלטה שלכם. בחלון ההתקדמות מופיעה תיבת החלטה עם הסבר בעברית ואפשרויות. ההחלטה עצמה אינה שולחת דבר לספק; רק ההמשך שאחריה שולח. כל החלטה נרשמת לצמיתות ביומן העלויות, ואפשר רק להעלות מגבלות, לא להוריד.

ניסיון חוזר אוטומטי. כשהספק דוחה בקשה במפורש לפני שעיבד אותה (HTTP 429 "יותר מדי בקשות", 529 עומס, או שגיאות שרת 500/502/503/504), הבקשה לא חויבה, והיא נשלחת שוב אוטומטית עד שלוש פעמים, אחרי 2, 8 ו־20 שניות (או לפי Retry-After של הספק, עד 60 שניות). ניתוק, timeout או כשל אחרי שהתשובה התחילה להגיע אינם נשלחים שוב אוטומטית ומגיעים לתיבת ההחלטה.

תשובות בקורת שמורות שלא נוצלו. בעבודות שרצו לפני עדכון הבדיקה, ביקורות רבות סומנו "דורש בדיקה אנושית" רק כי המודל עטף את הציטוט במירכאות. כשעבודה כזו מושהית או עצורה, מופיע בחלון העיבוד כפתור לבדיקה מחדש. הבדיקה קוראת שוב את התשובות השמורות בלי קריאה לספק, ופותחת מחדש פרקים שנמצאו בהם ממצאים מהותיים. התיקונים והבדיקות החוזרות נשלחים לספק רק כשהעבודה ממשיכה.

מקטעים בלי מה לתרגם, כמו כתובות אתרים, דוא"ל, מספרים או ISBN, נשמרים כפי שהם ואינם נשלחים לבדיקת איכות.

מחברת הספר

בתרגום אוטומטי, אחרי כל פרק המודל מעדכן מחברת ספר: שמות והתרגום שנבחר להם, מין דקדוקי וצורות פנייה, קול ומשלב של דמויות, מונחים, משחקי מילים ומוטיבים, סיכום לכל פרק וסיכום מצטבר של העלילה. בספר עיוני המחברת מתמקדת במונחים ובהגדרות, בהוגים ובחיבורים המצוטטים, בקיצורים ובסימון, והסיכום המצטבר הוא של הטיעון. המתרגם ובדיקת הפרקים מקבלים את החלקים הרלוונטיים מהמחברת כדי לשמור על עקביות לאורך הספר. אין צורך לעשות דבר; אפשר להוריד את המחברת (Markdown) בדף התוצאה.

  • הסיכום המצטבר אינו מוגבל במספר מילים: המודל מתבקש לשמור כל קו עלילה, תת־עלילה, קשר, סוד ושאלה פתוחה שעשויים להיות חשובים (בספר עיוני: התזה, שלבי הטיעון, ההגדרות, ההבחנות ועמדות המחברים המצוטטים), ולדחוס אירועים ישנים במקום להשמיט חוטים. גבול בטיחות: 60,000 תווים. בתיבת ההחלטה אפשר לבחור לקצר אותו ל־300 מילים.
  • סיכום פרק עד 5,000 תווים; הערה ברשומה עד 2,000 תווים. כל קיצור מדווח כאזהרה ואינו נעשה בשקט.
  • המחברת מקבלת עד 24,000 טוקנים בכל קריאה (ולא יותר מעשירית מחלון ההקשר של המודל). אם הסיכום המצטבר ארוך מזה, מקצרים את אמצעו ושומרים את ההתחלה ואת האירועים האחרונים; הוא לעולם אינו מושמט.
  • המתרגם רואה גם את סוף הקטע הקודם, עד 4,000 תווים, כדי לשמור על רצף בין פרקים.

טבלת שמות ומונחים. לפני התרגום המודל קורא את המקור ובונה טבלה עם צורה עברית אחת לכל שם ומונח. בספרות: דמויות, מקומות, ארגונים, תארים ומונחים מומצאים. בספר עיוני או במאמר אקדמי: הוגים ומחברים שנדונים או מצוטטים בגוף הטקסט (לא כל פריט ברשימה הביבליוגרפית), חיבורים מצוטטים, אסכולות ומוסדות, ומונחי המפתח של המחבר, שמשתנים בנטייה כרגיל. במאמר שאינו מחולק לפרקים הטבלה נבנית מכל המאמר בבת אחת. אפשר לעיין בטבלה בקובץ המחברת שמורידים מדף התוצאה. הטבלה ננעלת אוטומטית, בלי שלב אישור, וניתנת למתרגם ולבודקים בכל קריאה. שמות חדשים שמופיעים בהמשך נוספים אליה, ושם שכבר בטבלה אינו משתנה. מותר להשתמש בניקוד כדי להבדיל בין שמות (למשל שמות שהיו נכתבים באותן אותיות). אין בדיקת שמות בקוד; העקביות נשענת על הטבלה ועל הבדיקה הרוחבית.

בדיקה רוחבית. קודם נבנית טבלת שמות: המודל קורא את הספר המקורי, קטע אחר קטע, ומרכז שמות, תארים ומונחים מומצאים; בספר עיוני גם הוגים ומחברים, חיבורים מצוטטים ומונחי מפתח (מותר ניקוד); הטבלה ננעלת. אחר כך הבדיקה משווה את המקור עם התרגום בחלונות של 8 פרקים עם פרק אחד חופף (1–8, 8–15, 15–22 …); הפרק החופף, שכבר נבדק, הוא הקובע. שמות, מונחים, הפניות ורצף לא עקביים מתוקנים אוטומטית ונבדקים שוב, והנוסח העברי הקודם נשמר. ספר קיים שכבר תורגם עם מחברת ספר אפשר לבדוק בלחיצה על "להכין בדיקה רוחבית" (או "להריץ שוב בדיקה רוחבית") בדף התוצאה, ואחר כך על "המשך". קריאות בתשלום לספק מתחילות רק כשתלחצו ״המשך״. הרצה חוזרת שולחת מחדש רק טקסט שהשתנה.

מאמרים: הערות שוליים, רשימת מקורות ועימוד

ב־PDF (דיגיטלי או סרוק) התוכנה מזהה לפי גובה השורות ומיקומן את הערות השוליים בתחתית העמוד (גם הערה שנמשכת לעמוד הבא), את סימני ההערה בטקסט, את הכותרות הרצות ומספרי העמודים שחוזרים בכל עמוד, ואת רשימת המקורות שאחרי הכותרת References / Bibliography וכדומה.

  • סימן הערה מועבר למתרגם כ־[^12] ונשמר במקומו בתרגום; אם המודל השמיט סימן, הוא מוחזר לסוף הקטע ומסומן לבדיקה.
  • ב־PDF המתורגם כל הערה מופיעה בתחתית העמוד שבו נמצא הסימן שלה, באות קטנה ובמספור המקורי; הערה ארוכה ממשיכה בתחתית העמוד הבא. ב־HTML ההערות מקושרות ומרוכזות בסוף.
  • רשימת המקורות נשארת בשפת המקור, ללא קריאה למודל, ומוצגת משמאל לימין. גם כותרות רצות ונוסחה שעומדת לבדה אינן נשלחות לתרגום.
  • מתמטיקה אינה סימן הערה: ספרה אחרי משתנה (x2), אות יוונית או סמל מתמטי, ומספרי משוואות כמו (3), נשארים כפי שהם.

הזיהוי מבוסס על כללים גאומטריים; הערה שהסימן שלה לא נמצא מוצגת במקומה המקורי. כדאי לעבור על מאמר ראשון ולבדוק.

ספרים סרוקים

עמודים בלי טקסט מוטמע (סריקות) מזוהים אוטומטית לפני התרגום, בשני שלבים:

  • זיהוי מקומי (OCR) בתוכנת Tesseract במחשב שלכם, ללא עלות. אנגלית משתמשת במודל של ההתקנה; צרפתית ויפנית משתמשות במודלים שמצורפים לפרויקט. בחרו את שפת המקור במפורש: בקובץ סרוק אין טקסט לזיהוי השפה.
  • בדיקת המודל (ברירת המחדל במודל משלכם): כל עמוד נשלח למודל המתרגם יחד עם תמונת העמוד וטקסט ה־OCR. המודל מחזיר את הטקסט המדויק של העמוד בשפת המקור: מתקן טעויות זיהוי ומשלים שורות חסרות. נוסחאות נכתבות בצורה מתמטית ומוגנות בתרגום. המודל צריך לקרוא תמונות. אפשר לבחור "זיהוי מקומי בלבד" בהגדרות.

מילים שהמודל שינה נשמרות בלי מיקום בעמוד ובביטחון 0, כדי שיהיה ברור מאיפה בא כל קטע. עמוד שבו הזיהוי המקומי והמודל שונים מאוד מסומן כחריג בדף התוצאה; כדאי לבדוק אותו. טקסט מזוהה תמיד נשלח לבדיקת האיכות של המקטע ברמת "נבדק".

עלות. הזיהוי המקומי חינמי. בדיקת המודל היא קריאה אחת לעמוד (תמונה וטקסט), והאומדן מוצג לפני התרגום. עלות התרגום עצמו מחושבת רק אחרי הזיהוי, מול אותו תקציב; אם היא חורגת, התרגום נעצר ותיבת ההחלטה מציעה להעלות את התקציב. אם קריאת הבדיקה נכשלת, תיבת ההחלטה מציעה גם להמשיך עם הזיהוי המקומי בלבד. תוצאות שכבר התקבלו לא נשלחות שוב.

לא נתמכים: כתב יד, טקסט בתוך איורים, ופריסת עמוד מורכבת מעבר למה ש־Tesseract מזהה.

הפעלה ומגבלות

להפעלה ב־Windows לחצו על Run Scholarly Translation.vbs או הריצו .\run-ui.ps1. בהתקנה ראשונית השתמשו ב־Install.bat. השאירו את חלון השרת פתוח. מינוי ChatGPT או Claude Code אינו מפתח API לתרגום.

אם PowerShell חוסם סקריפטים, השתמשו בקובץ ה־VBS או ב־powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-ui.ps1. ההגדרה חלה על התהליך הזה בלבד ואינה משנה את מדיניות המחשב.

הקלט מוגבל ל־2,000 עמודים/פרקים ול־3,000,000 תווים. ספרים סרוקים נתמכים: ראו ספרים סרוקים. PDF מתורגם נבנה מחדש ואינו משחזר עימוד מקורי; EPUB שומר את הארכיון והעיצוב, עם מגבלות במקטעים שאוחדו. עימוד מורכב ואיכות תרגום דורשים בדיקה על מסמכים אמיתיים.

מתמטיקה. ב־PDF המתורגם, סמלים שחסרים בגופן העברי (∑, √, ≤, אותיות יווניות, מעריכים ואינדקסים) מצוירים אוטומטית בגופן מתמטי (Noto Sans Math, ואחריו Noto Sans), ונוסחה בשורה נפרדת מוצגת משמאל לימין. ב־EPUB, נוסחאות MathML עוברות את התרגום מוגנות ומוחזרות למקומן כפי שהן; ב־PDF/HTML מוצגת גרסה טקסטואלית שלהן. קטע שכולו נוסחה אינו נשלח לבדיקת איכות. ב־PDF דיגיטלי הנוסחאות נקראות מהטקסט המוטמע; בספר סרוק הן מזוהות בבדיקת המודל (ראו ספרים סרוקים).

השרת מאזין רק במחשב המקומי. המקור, הטיוטות ויומני העבודה נשמרים ב־outputs/ui/; מפתחות שמוזנים בממשק נשמרים בזיכרון, ובמנהל האישורים של Windows רק אם סימנתם "לזכור", ושדות הסיסמה מתרוקנים אחרי שמירה.

Help and transparency

This page explains every step, setting and estimated cost of the local translation tool. It is built by your local server and sends no information to any external server.

Steps

  1. Choose a file — a PDF with embedded text (not a scan without text) or an EPUB, up to 25MB.
  2. Options — translation profile (academic/literary), review level (fast/checked/in-depth), model (Auto for a simulated trial preview, or your own model with an API key), source language, budget (a required field with your own model; there is no built-in cap — the limit you set is enforced as a hard stop, and the conservative reservation must fit within it), and PDF font.
  3. Translate — click the button. With your own model you will be asked to approve actually sending to the selected provider(s), and you will see a cost estimate in advance.
  4. Progress tracking — a real progress percentage (not time-based), based on chapters/stages actually completed; you can pause and resume the job automatically. If translation stops, a decision box appears with an explanation and options.
  5. Result — download the translated file (PDF/EPUB/HTML), optional review and manual editing, and change the PDF font without calling the model again.
  6. The library — all translations, finished and in progress, are stored on your computer and available from the "Library" button at the top of the page. Details.

Models, QA and API keys

Auto is simulated: it sends no text to any provider, requires no key, and returns placeholder text only — never a real translation.

With your own model, you choose a translator model from the catalog (below) or define an "Other" model (an ID, a provider, and for an OpenAI-compatible address, also an endpoint). Quality review (QA — "semantic_reviewer" and "chapter_qa") defaults to the same model as the translator, and can be changed separately. Keys are kept in the memory of the local server for the current run: not in the settings file, not in a log, not in the browser's localStorage and not in environment variables. If you tick "Remember on this computer", the key is also stored encrypted in the Windows Credential Manager under your user account and reloaded when the program starts; "Delete the saved keys from this computer" removes it from there. The key icon in the header turns gold when a key is present, with a green dot when it is saved on this computer. Starting the server again resets them; resuming a paused job asks for the keys again and uses the saved job.

Token uncertainty, input/output and QA/cache cost

The token count in the preview is an upper bound estimate, not an official provider count: mixed text (Hebrew/Latin/Japanese) may be counted differently from what the provider actually counts at real send time. The "expected" estimate assumes about 35% use of the output cap, zero corrections and zero cache hits (a full cache miss); the conservative ("ceiling") estimate also includes one bounded correction and one focused re-check, and assumes a full cache write. Neither estimate is a provider quote, and the actual (observed) cost may differ — it is shown separately from the reserved/planned budget during a real run.

Translation profile and review level

According to the linked provider descriptions above, the models are intended for different kinds of work. These are the providers' descriptions, not a ranking of Hebrew translation quality in this project.

Luna — focused tasks

According to OpenAI, intended for focused tasks at large scale, at a low price. It lets you check more samples on a small budget; terminology and complex arguments should be examined in particular.

Sol — complex professional work

This is how OpenAI describes the model. The regular input and output price is 20 times that of Luna; the higher price is not evidence of improvement in your particular translation.

Sonnet — speed and capability

Anthropic describes it as a balance between speed and capability. The regular input and output price is the same as Sol, but cache and thinking rates may change the total cost.

Opus — long-running work

According to Anthropic, intended for complex, long-running work. The input and output price is double that of Sonnet, and thinking is always on; it has not been shown in the project that it always translates or reviews better.

You can choose a cheap translator and a different reviewer, or check a source sample with several models. The right choice depends on the exact meaning, terminology, style and QA findings of your text; a high price or a large context window alone are not proof of quality.

Academic preserves semantic precision, terminology, footnotes and citations. Literary preserves voice, register and dialogue.

Fast: translation only, no routine QA review. Checked: review of every segment that has something to translate, except short headings (up to three words), + chapter review. In-depth: review of every segment, including headings, + chapter review.

A substantive finding (MAJOR or CRITICAL) from a segment review is corrected automatically and checked again. From the chapter review, only consistency and continuity findings are corrected automatically; other chapter review findings are kept as notes. A finding whose quote is not found in the text, or one the model retracted, is omitted and not corrected.

There is no validated quality ranking of the models. A research quality pilot with human judges on real source segments has not yet been run (the pilot is currently blocked for lack of an approved representative input, provider authorization and human judgment). A more expensive model is not guaranteed to be better for your text; we recommend running a small pilot on part of your document and checking the QA yourself before relying on a single model.

Pause, resume and results

Pause saves the response of the active call and stops before another request. Resume uses the saved source, plan and results: stages already completed are not sent or billed again. A request whose outcome is unknown is not automatically re-sent; it is shown in the decision box so you can choose yourself whether to send again.

Download builds the document from the saved draft. Review and edit shows source beside target and keeps a previous version. After an edit, the old quality review is marked as out of date; editing is not research approval.

The percentages under the book reflect completed stages and chapters, and are not a time forecast. On pause and on failure the book stops flipping pages. All results are unapproved drafts, even after automatic checks.

The library

The Library button at the top of the page opens all translations saved on your computer, in two tabs:

  • Ready — completed translations. Clicking a document shows download in the source format (PDF or EPUB) or as HTML, PDF font selection, and opening for review and editing.
  • In progress — translations not yet completed: paused, stopped or interrupted. For each document the status, completed chapters and segments, and spending out of the budget are shown. A document waiting for your decision is marked "Decision required". Open and resume (or Open and decide) returns you to the progress window.

Partial download (in the "In progress" tab) builds a file from what has already been translated; segments not yet translated remain in the source language. The .he.partial suffix in the file name distinguishes it from a full translation. The download sends no call to the model.

Delete permanently deletes the translation, the copy of the source file, the book notebook and the document's cost log. You will be asked to confirm, and it cannot be undone. A document being translated right now cannot be deleted: pause it first. Deleting does not cancel a charge already recorded by the provider.

When translation stops

To avoid wasting money and double billing, translation stops when something is uncertain and waits for your decision. In the progress window a decision box appears with an explanation in Hebrew and options. The decision itself sends nothing to the provider; only the continuation after it does. Every decision is permanently recorded in the cost log, and limits can only be raised, not lowered.

Automatic retry. When the provider explicitly rejects a request before processing it (HTTP 429 "too many requests", 529 overloaded, or server errors 500/502/503/504), the request was not billed and is sent again automatically up to three times, after 2, 8 and 20 seconds (or per the provider's Retry-After, up to 60 seconds). A disconnect, timeout, or failure after the response began to arrive is not re-sent automatically and reaches the decision box.

Saved cross-review responses that were not used. In jobs that ran before the validation update, many reviews were marked "needs human review" only because the model wrapped the quote in quotation marks. When such a job is paused or stopped, a re-check button appears in the processing window. The re-check re-reads the saved responses without a call to the provider, and reopens chapters in which substantive findings were found. Corrections and re-checks are sent to the provider only when the job continues.

Segments with nothing to translate, such as URLs, email addresses, numbers or ISBNs, are kept as they are and are not sent to quality review.

The book notebook

In automatic translation, after each chapter the model updates a book notebook: names and the translation chosen for them, grammatical gender and forms of address, voice and register of characters, terms, wordplay and motifs, a summary of each chapter and a cumulative plot summary. In a scholarly book the notebook focuses on terms and definitions, thinkers and cited works, abbreviations and notation, and the cumulative summary is of the argument. The translator and the chapter review receive the relevant parts of the notebook to keep consistency throughout the book. You do not need to do anything; you can download the notebook (Markdown) on the result page.

  • The cumulative summary has no word limit: the model is asked to keep every plot line, subplot, relationship, secret and open question that may matter (in a scholarly book: the thesis, the steps of the argument, definitions, distinctions and positions of the cited authors), and to compress old events rather than drop threads. Safety limit: 60,000 characters. In the decision box you can choose to shorten it to 300 words.
  • A chapter summary is up to 5,000 characters; a note in an entry is up to 2,000 characters. Every shortening is reported as a warning and is never done silently.
  • The notebook receives up to 24,000 tokens per call (and no more than a tenth of the model's context window). If the cumulative summary is longer than that, its middle is shortened and the beginning and the latest events are kept; it is never omitted.
  • The translator also sees the end of the previous passage, up to 4,000 characters, to maintain continuity between chapters.

Table of names and terms. Before translating, the model reads the original and builds a table with one Hebrew form for each name and term. In fiction: characters, places, organizations, titles and invented terms. In a scholarly book or an academic article: thinkers and authors discussed or cited in the running text (not every item of the bibliography), cited works, schools and institutions, and the author's key terms, which inflect as usual. An article without chapters is read as a whole in one step. You can read the table in the notebook file downloaded from the result page. The table is locked automatically, with no approval step, and is given to the translator and the reviewers on every call. New names that appear later are added to it, and a name already in the table does not change. Vowel marks (niqqud) may be used to distinguish between names (for example names that would otherwise be written with the same letters). There is no name check in code; consistency relies on the table and the cross-review.

Cross-review. First a name table is built: the model reads the original book, passage by passage, and collects names, titles and invented terms; in a scholarly book also thinkers and authors, cited works and key terms (vowel marks allowed); the table is locked. Then the review compares the source with the translation in windows of 8 chapters with one overlapping chapter (1–8, 8–15, 15–22 …); the overlapping chapter, already checked, is the authority. Inconsistent names, terms, references and continuity are corrected automatically and re-checked, and the previous Hebrew wording is kept. An existing book that was already translated with a book notebook can be checked by clicking "Prepare cross-review" (or "Run cross-review again") on the result page, and then "Continue". Paid calls to the provider begin only when you click "Continue". A repeated run re-sends only text that changed.

Articles: footnotes, bibliography and layout

In a PDF (digital or scanned) the software identifies, by line height and position, the footnotes at the bottom of the page (including a note that continues onto the next page), the note markers in the text, the running headers and page numbers that repeat on every page, and the bibliography after a heading such as References / Bibliography.

  • A note marker is passed to the translator as [^12] and kept in its place in the translation; if the model omitted a marker, it is restored at the end of the passage and flagged for review.
  • In the translated PDF each note appears at the bottom of the page where its marker is, in small type and with the original numbering; a long note continues at the bottom of the next page. In HTML the notes are linked and gathered at the end.
  • The bibliography stays in the source language, with no call to the model, and is displayed left to right. Running headers and a standalone formula are also not sent for translation.
  • Mathematics is not a note marker: a digit after a variable (x2), a Greek letter or a mathematical symbol, and equation numbers such as (3), are left as they are.

Detection is based on geometric rules; a note whose marker is not found is shown in its original place. It is worth going over a first article and checking it.

Scanned books

Pages without embedded text (scans) are detected automatically before translation, in two stages:

  • Local recognition (OCR) with Tesseract on your computer, at no cost. English uses the installation's model; French and Japanese use models bundled with the project. Choose the source language explicitly: a scanned file has no text from which to detect the language.
  • Model check (the default with your own model): each page is sent to the translator model together with the page image and the OCR text. The model returns the exact text of the page in the source language: it fixes recognition errors and fills in missing lines. Formulas are written in mathematical form and protected in translation. The model must be able to read images. You can choose "Local recognition only" in the settings.

Words the model changed are kept with no position on the page and with confidence 0, so it is clear where each passage came from. A page where local recognition and the model differ greatly is flagged as an exception on the result page; it is worth checking. Recognized text is always sent to segment quality review at the "Checked" level.

Cost. Local recognition is free. The model check is one call per page (image and text), and the estimate is shown before translation. The cost of the translation itself is computed only after recognition, against the same budget; if it exceeds it, translation stops and the decision box offers to raise the budget. If the check call fails, the decision box also offers to continue with local recognition only. Results already received are not sent again.

Not supported: handwriting, text inside illustrations, and complex page layout beyond what Tesseract recognizes.

Running and limits

To run on Windows, click Run Scholarly Translation.vbs or run .\run-ui.ps1. For first-time installation use Install.bat. Keep the server window open. A ChatGPT or Claude Code subscription is not an API key for translation.

If PowerShell blocks scripts, use the VBS file or powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-ui.ps1. The setting applies to this process only and does not change the computer's policy.

Input is limited to 2,000 pages/chapters and 3,000,000 characters. Scanned books are supported: see Scanned books. A translated PDF is rebuilt and does not reproduce the original layout; EPUB preserves the archive and styling, with limitations in segments that were merged. Complex layout and translation quality require checking on real documents.

Mathematics. In the translated PDF, symbols missing from the Hebrew font (∑, √, ≤, Greek letters, exponents and subscripts) are drawn automatically in a math font (Noto Sans Math, then Noto Sans), and a formula on its own line is displayed left to right. In EPUB, MathML formulas pass through translation protected and are restored in place as they were; in PDF/HTML a textual version of them is shown. A segment that is entirely a formula is not sent to quality review. In a digital PDF the formulas are read from the embedded text; in a scanned book they are detected in the model check (see Scanned books).

The server listens only on the local computer. The source, drafts and job logs are stored in outputs/ui/; keys entered in the interface are kept in memory, and in the Windows Credential Manager only if you ticked "Remember"; password fields are cleared after saving.
